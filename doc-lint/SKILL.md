# ドキュメント検査

本規約と `docs/CLAUDE.md` の規約のうち、機械的に判定できるものだけを見る。リポジトリのルートで実行する。

```bash
python3 .agents/conventions/doc-lint/lint.py .
```

引数は走査の起点。`docs` を渡せば設計文書だけを見る。指摘が0件なら終了コード0、1件でもあれば1を返す。

PRでは回らない。編集したセッションの終わりにフックが同じ検査を流して止める。フックの外で編集したときは手で流す。

## 走査の範囲

起点配下のMarkdownのうち、gitが追跡するものと、gitignoreが無視していないものを見る。生成物をどこまで無視するかは各リポジトリの `.gitignore` が決める。検査は自前の一覧を持たない。

`.agents/` は見ない。外から取り込んだ資産の置き場で、規約に従わせる相手ではない。

ネストした別リポジトリとsubmoduleの中身はgitが挙げない。子リポジトリのMarkdownは、そのリポジトリの検査が受け持つ。

起点がgitの作業ツリーの外にあるときは、gitの言い分を添えて止まる。

## 見ているもの

対象は2種類ある。`docs/` 配下の設計文書と、それ以外のMarkdown。

| 種別 | 内容 | 対象 |
|---|---|---|
| フロントマター無し | `---` で始まらない文書 | 設計文書 |
| source_of_truth無し / input_documents無し / output_documents無し | 必須フィールドの欠落 | 設計文書 |
| 宛先が存在しない | 入出力に書いたパスの文書が無い | 設計文書 |
| 辺が片側だけ | Aのoutputに書いたのに、Bのinputに逆向きが無い | 設計文書 |
| リンク切れ | 本文の相対リンクの先が無い | 設計文書 |
| 確定していない記述 | TODO・将来・変更予定・旧:・従来 | 設計文書 |
| 太字 | `**` による強調 | 全Markdown |
| 括弧注釈 | `（）` による補足。制約名の限定辞は除く | 全Markdown |

設計文書は `docs/` 配下のうち `CLAUDE.md` を除いたもの。`CLAUDE.md` と `SKILL.md` は入出力グラフのノードではないため、フロントマターを要求する検査から外れる。太字と括弧注釈は規約そのものなので、これらにも掛かる。

太字と括弧注釈はフロントマターを含む全体を見る。コードフェンスの中と、バッククォートで囲んだ範囲は見ない。

## 直し方

辺の片側だけは、下流が `input_documents` に書いた相手の `output_documents` へ自分を足す。上流が先に書き、下流が受けるのが向き。

括弧注釈の指摘は、本文として言い切るか、消す。制約定義マスタの名称に含まれる `（教員）` `（講座）` のような限定辞は名前の一部なので、`lint.py` の `NAME_QUALIFIERS` が除いている。

確定していない記述は文書から落とし、残作業なら `gh issue create` でissueにする。

## 見ていないもの

要件・仕様・実装の染み出し、二重管理、粒度。これらは読まないと判定できない。検査が0件でも、内容の確認は別に要る。
